# Introduction to Relational Databases

Welcome to your very first step in mastering SQL! In this lesson, we will uncover what a relational database is and why it forms the backbone of modern corporate finance ledgers, web applications, and analytics models.

<Info title="Why Databases?">
  Spreadsheets are great for modeling small worksheets, but once you scale to millions of order lines, relational databases are necessary to enforce data structures and run rapid indexing queries.
</Info>

### Relational Tables & Grid Sheets

At its core, a relational database stores information in **tables** (similar to spreadsheets). Each table has a pre-defined **schema** outlining the columns, and holds multiple **rows** (records).

Let's look at the standard structural elements:
1. **Primary Key**: A column that uniquely identifies a row (e.g., `user_id` or `order_id`).
2. **Foreign Key**: A column in one table referencing the Primary Key of another table, forming a connection or **relation** (e.g., `user_id` inside the `orders` table).

<Tip title="Memory Shortcut">
  Primary Keys enforce *uniqueness* within a table. Foreign Keys enforce *connections* between tables.
</Tip>
